# План реализации и делегирование

## Порядок

1. Зафиксировать контракты, роли и ограничения MVP; подготовить окружение.
2. Реализовать миграцию, seed, вход и read-only профиль.
3. Реализовать заявку, атомарную историю/аудит/уведомления, идемпотентность, решение человеком.
4. Параллельно собрать интерфейс по контракту API.
5. Добавить назначенный курс, тест и помощника с источниками/отказом.
6. Подключить интерфейс к реальному backend, собрать контейнеры и проверить сквозной путь.
7. Проверить права, сохранность заполненной базы после миграции и повторных команд; записать пределы проверки.

## Делегирование

Технический лидер владеет docs/api-contract.md, общими моделями, миграциями и интеграцией. Изменения контракта требуют согласования до параллельной работы.

| Задача | Область записи | Критерий готовности |
| --- | --- | --- |
| Frontend | frontend/ | Все страницы работают по контракту; адаптивная компоновка, состояния загрузки/ошибки, без вымышленных API |
| Backend | backend/ | Авторизация, объектные права, атомарные изменения, аудит, тесты |
| Проверка | backend/tests/, отчёт | Изоляция сотрудников/команд, собственное согласование запрещено, повтор команды, сохранение данных |
| Инфраструктура | compose.yaml, README.md | Понятный запуск, переменные окружения, сохранение данных, healthchecks |

Ветки и PR нужны при совместной Git-работе; не создавать отдельные Git-репозитории внутри текущего каталога. Не коммитить чужие файлы родительского проекта. Интегрировать небольшими порциями, сначала контракты и backend, затем реальные вызовы UI.

Следующий этап: настоящий RAG и оценка ответов, RU/KZ, SSO, согласованные интеграции, PostgreSQL-конкурентные тесты в CI. Каждый пункт отдельной задачей, с собственными критериями приёмки.

## Выполнено в первой итерации

Контракты, миграция и seed, backend, адаптивный интерфейс, сценарий заявки, Academy, уведомления, аудит и помощник по источникам реализованы. 73 backend-теста и браузерный сценарий пройдены; production-сборка web прошла. Docker Compose дополнен запуском без локальных Python/Node.js, healthcheck интерфейса, выбором портов и CI-сценарием с PostgreSQL. Генеративный RAG не реализован. Фактические проверки Docker/PostgreSQL и их пределы — в verification.md.

Делегирование фактически использовано для frontend и backend-тестов в первой итерации. Контракты, модели, миграция, инфраструктура, интеграция и финальный браузерный прогон выполнялись основным агентом. Дальнейшие независимые задачи: конкурентные PostgreSQL-тесты; генеративный RAG с оценкой и правами; локализация RU/KZ. Результат каждого направления принимает человек по demo-scenarios.md.
