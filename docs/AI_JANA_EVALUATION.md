## Evaluation basis and method

The Challenge 02 rubric gives **AI Jana 15%** and judges answer quality, sources, refusal when evidence is absent, and access rights. The project's [transcription of the organizer PDF](audit-case-02.md) identifies the source as *Jana Post Terricon Hackathon 2026*, physical PDF page 18 (printed page 17). The evaluation below tests those dimensions, plus catalog discovery, course scope, and saved-conversation access.

I migrated an **isolated PostgreSQL 17 container with tmpfs** to Alembic `0014`. The test fixture created and dropped its own schema, seeded demo users and six built-in knowledge articles, imported the **11 actual files** in [the corpus manifest](../backend/app/corpus_manifest.json) from `knowledge_base_docs/`, and attached `HR-01.pdf` to the assigned demo course. All 11 imported files start with `access_scope=all`; each is labeled synthetic demo material except the supplied, unverified Labor Code snapshot. Mock 1C:ZUP was used. External LLM calls were disabled for the 20-question matrix; a separate adversarial provider response was mocked. No shared Compose service, persistent Docker volume, production database, or live provider was used.

**Pass rule:** the response must answer the question from authorized evidence, cite a passage that supports the answer when using content, or refuse with no source when reliable evidence is absent. Catalog answers are checked against file titles and formats in database metadata; `sources=[]` is expected for this metadata path. A correct citation attached to an irrelevant answer is a failure. IDs below are evaluation labels; database IDs are temporary.

## Focused safety probes outside the 20-question score

- **History and role checks that held:** After an answered `LOG-02` file was changed from `all` to `hr_admin` inside the disposable schema, its saved answer replay became «Источники этого ответа больше недоступны» with `sources=[]`. A new employee query did not cite either of the two files whose scopes were changed, and a new catalog query omitted their titles. The existing focused history, inventory, retrieval and mocked-LLM suites passed **17/17** on the same isolated PostgreSQL container; they cover conversation ownership, course isolation, idempotent retry, catalog replay and citation reauthorization.
- **Direct citation endpoint access gap:** With an `OPS-03` parent `KnowledgeFile` changed to `hr_admin` while its previously ingested chunks remained `all`, an employee request to `/api/knowledge/{document_id}` still returned **200** with the restricted title and passage. [The endpoint](../backend/app/modules/assistant.py) checks the chunk scope but not the parent file scope, unlike retrieval and history replay. This is a reproducible leak for a known chunk ID after a file visibility change; the matrix score must not be interpreted as an RBAC sign-off.
- **Mocked LLM grounding failure:** A mock provider returned «Отпуск автоматически одобряется после подачи заявки.» for HR1. [The wording guard](../backend/app/modules/assistant_llm.py) accepted it and the API appended `[1]` to `HR-01` §02, although that passage describes submission, not automatic approval. The guard checks overlapping words, numbers and a small forbidden-output list; it does not establish entailment. No real provider was contacted.

## Top three weaknesses and minimal fixes

1. **Critical — source endpoint can bypass changed file visibility.** Make `/api/knowledge/{document_id}` join `KnowledgeFile` and require both chunk and parent scopes to be readable, using the same rule as assistant retrieval/history. Add a PostgreSQL regression that changes only the parent file scope and expects 404 for an employee on the known chunk ID, while HR remains authorized. Review any other direct source routes for the same mismatch.
2. **High — a fluent but unsupported LLM claim can receive a valid citation.** Until a claim-level check is available, use the existing extractive passage for consequential HR/approval answers when generated wording adds an unsupported decision or causal claim. Extend mocked-provider tests with the automatic-approval counterexample and other unsupported but lexically similar claims. A citation should be added only to wording supported by its passage.
3. **Medium — retrieval/evidence selection misses supported questions and surfaces template filler.** Exclude «Практический контекст»/«Проверка понимания» boilerplate from answer evidence, select answer-bearing sections for status and approval questions, and allow a bounded summary from adjacent sections for broad lifecycle/onboarding questions. Keep refusal when the selected evidence still cannot answer. Re-run HR3, HR4, LOG2, LOG4, COURSE2 and AUTH2 as targeted acceptance cases.

## Evidence and limits

The diagnostic used the current [assistant route](../backend/app/modules/assistant.py), [retrieval](../backend/app/modules/retrieval.py), [course route](../backend/app/modules/academy.py), [history reauthorization](../backend/app/modules/assistant_conversations.py), [file visibility service](../backend/app/modules/knowledge_files.py), the seeded demo articles in [seed.py](../backend/app/seed.py), and the actual files listed in [corpus_manifest.json](../backend/app/corpus_manifest.json). The one-off diagnostic **executed** under pytest (`1 passed`, one existing Starlette/httpx deprecation warning); its quality judgments are the separate 14/20 matrix above. The targeted regression run passed `17 passed`, one such warning. The diagnostic script was removed after evidence was recorded.

The original corpus has no role-restricted files, so role-dependent file behavior was probed by changing scopes **only in the disposable test schema**; the HR-only seeded article supplied a baseline role check. The direct endpoint finding applies when a parent file's scope changes without rewriting its chunks. Live-provider factual accuracy, current legal validity of the supplied Labor Code copy, browser presentation, concurrent history access and deployment configuration were **not tested** here. No Jana Post policy, operational rule or legal entitlement is inferred from synthetic material.
