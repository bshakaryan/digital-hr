# JanaМен Digital HR

Проект начинается с пустого каталога. Предыдущие инструкции о НарядAI относятся к другому продукту; сохраняем их требования к правам, аудиту, миграциям и честному описанию проверок. Flutter и native-stub здесь не используются: Digital HR требует адаптивный web-прототип.

Основание: Challenge 02 из Jana Post Terricon Hackathon 2026 и обсуждение команды. Цель: вход → профиль → заявка на отпуск → решение человека → уведомление, а также курс и помощник по демонстрационной базе знаний.

## Демо каталог Jana People

В `ZUP_MODE=mock` команда `python -m app.provision_jana_people` добавляет 30 вымышленных сотрудников в семь подразделений, с устойчивыми `people-001`…`people-030` и реальными связями `manager_id`. Команда повторяема, не перезаписывает существующие записи и не выдаёт доступные учётные данные новым сотрудникам. Четыре исходных демонстрационных пользователя и их пароли сохраняются. В едином Web Service команда запускается после первичного seed; в отдельном Compose стенде её можно вызвать вручную после миграций и seed. При `ZUP_MODE=real` команда отказывается работать.

Любой вошедший сотрудник видит безопасный корпоративный каталог и структуру; полные профили и кадровые данные остаются в прежней области доступа. Синтетические записи служат только для демонстрации и не являются кадровыми данными Jana Post.

Для наполнения календаря после `app.provision_jana_people` выполните `python -m app.provision_jana_people_leave` в backend-контейнере с `ZUP_MODE=mock` и доступным mock 1С:ЗУП. Команда создаёт 30 помеченных учебных заявок у существующих синтетических сотрудников в восьми подразделениях: 17 одобренных, четыре `submitted`, пять `manager_approved`, четыре отклонённые. Первые 15 заявок и их ключи сохранены; дополнительные 15 заполняют первые строки общего календаря. Даты рассчитываются для текущего и следующего месяца по времени Кызылорды; оба месяца должны поддерживаться текущим календарём mock 1С (2026–2028). Одобрения проходят существующие этапы решения руководителя и HR с расчётом, списанием, историей, аудитом и уведомлениями. Повтор в том же месяце не создаёт дубликаты и не меняет уже существующие заявки. При пересечении с другой действующей заявкой команда останавливается без перезаписи. Запуск явный; в реальном режиме команда отказывается работать. Две из первых семи учётных записей — HR Алия и сотрудник Данияр — не имеют назначенного руководителя, поэтому сервис не создаёт для них отпуск без законного согласующего.

## Демо курсы и аналитика Jana Academy

При деплое корневого Dockerfile для одного Web Service исходный корпус и демо Academy наполняются автоматически после миграций и начального seed; команда ниже нужна для отдельного Docker Compose стенда. Локальные пользовательские данные Compose не переносятся в облако через Git. Подробности и ограничения хранения — в [deployment.md](deployment.md).

После импорта исходных документов и `docker compose up -d --build` выполните `docker compose exec -T backend python -m app.provision_academy_demo`. Команда использует существующие сервисы Academy и проверяет учебные вопросы по индексированным фрагментам синтетических документов. На новой mock-базе она создаёт 12 помеченных `DEMO / SYNTHETIC` курсов, 16 прежних назначений `legacy` и 4 новых назначения `onboarding` для `employee@example.com`; три опубликованных демо курса открывает для самостоятельной записи. С учётом четырёх начальных назначений seed получается 24 назначения. Из четырёх курсов адаптации один завершается через изучение материала и правильный ответ на тест, один остаётся в процессе, два не начаты: Jana Journey показывает 1/4 и 25%. `outsider@example.com` остаётся без назначений адаптации для проверки пустого состояния. Запуск разрешён только при `ZUP_MODE=mock` и точных синтетических идентификаторах; все демо курсы должны содержать только материалы `synthetic_demo`. Существующие назначения `legacy`, их сроки, прогресс и завершение не меняются и не переклассифицируются. Повторный запуск не создаёт новых назначений и не начисляет XP повторно. Полностью завершённый маршрут среди доступных демо логинов не создаётся: ранее назначенные курсы нельзя дублировать под новым треком. Содержание курсов не является официальной инструкцией Jana Post.

Учебный маршрут сотрудника использует существующие `DEMO-ONB-03`, `DEMO-LOG-02`, `DEMO-SAFE-02`, `DEMO-CS-02`; добровольная запись открыта для `DEMO-LOG-04`, `DEMO-SAFE-03`, `DEMO-CS-01`. Эти списки фиксированы, чтобы повторная команда не меняла категорию старых назначений и не перестраивала Jana Journey.

Для воспроизводимой просрочки в mock-режиме применяется `ACADEMY_DEMO_AS_OF=2026-10-17` (переопределяется через переменную среды; план сроков применяется только к новым назначениям). В реальном режиме используется текущая дата, демонаполнение запрещено. В Jana Academy HR видит обзор обучения, мониторинг и профили сотрудников; руководитель видит учебные профили только прямых подчинённых. Сотрудник видит отдельно назначенные курсы и опубликованный доступный каталог. Наличие курса в каталоге не означает его назначения.

## Исходный корпус AI Jana

`knowledge_base_docs/` содержит 11 исходных PDF/DOCX. После `docker compose up -d --build` первичную загрузку выполняют командой `docker compose run --rm --no-deps -v "${PWD}/knowledge_base_docs:/corpus:ro" backend python -m app.import_initial_knowledge --directory /corpus` в оболочке с корректной подстановкой текущего каталога. Команда использует тот же сервис, что HR upload `/api/knowledge-files`, и при повторе сообщает `duplicate` по SHA-256 без новых фрагментов. Файлы также доступны для ручной загрузки HR в интерфейсе. PDF без текстового слоя требует предварительного OCR вне приложения. Таблица результатов текущего локального импорта — в [verification.md](verification.md).
